# 实验方案：停顿触发的上下文补全

日期：2026-10-25
状态：**方案，未接线**。前置读数见 `REPORT.md` §10（60 对人工标注）、§11（场景修正）。

## 0. 要回答的问题

在“滚到某段 → 写意见 → 想引用/补全”的场景里，**键盘路径**（不选文本，停顿后等建议）
能否在精度可接受的前提下，替代或补充 quote chip？

LLM 不是只做“在 transcript 里找一段文本插入”。它要基于多路上下文给出**带类型的建议**：

```ts
type CompletionSuggestion =
  | { type: 'insert-passage'; passageId: string; text: string; sourceMessageId: string; confidence: number }
  | { type: 'mention'; token: string; kind: 'path' | 'task' | 'session' | 'file'; confidence: number }
  | { type: 'continue'; text: string; confidence: number }
  | { type: 'none'; reason: string };
```

四类动作分别评价，不混在一个“准确率”里。

## 1. 数据分层：现在能测什么，缺什么

| 层 | 数据 | 现状 |
|---|---|---|
| L0 回放层 | 草稿、窗口内消息、被引用段、距离 | **有**（509 个引用回合） |
| L1 视口层 | 滚动锚点、可见消息范围、viewport 高度 | **无**（transcript 不记录） |
| L2 会话状态 | 当前 task/goal、分支、打开的文件 | 部分可重建，暂不纳入 |

L1 是这次讨论的核心缺口。**在拿到真实滚动位置之前，只能用 oracle 消融给它定价**：
把“正确的源消息”当作视口，看排序能好多少；差值就是“捕获滚动位置”的价值上限。

## 2. 现有基线与分解（已跑，21 天）

语料：3,501 个真人回合；509 个含 ≥20 字符逐字引用；79 个“只引用无意见”（chip 的活）；
**430 个“引用 + 意见”**，其中 393 个能定位 ground-truth 段落。
草稿长度 p50 78 字符、p90 662 字符；来源距离 p50 1、p90 7。
105/430 回合有**第二段引用**（草稿重建只去掉最长的一段，需在多标签口径里单独处理）。

同一套 lexical 排序（字符 bigram Dice + 距离先验），只换候选池：

| 候选池 | 可评估 | top-1 | top-3 | 平均候选数 | 平均候选字符 |
|---|---:|---:|---:|---:|---:|
| source-only（完美视口，1 条消息） | 393 | 31.6% | **52.2%** | 17.2 | 1,482 |
| source-neighbors（完美视口 ±1） | 393 | 24.9% | **43.5%** | 24.3 | 2,188 |
| last-3（无视口信号） | 393 | 15.5% | 26.5% | 29.7 | 2,642 |
| last-5 | 393 | 15.3% | 29.0% | 41.9 | 3,708 |
| last-12 | 393 | 15.3% | 30.3% | 77.4 | 6,867 |

远处引用（94 个，距离 >3）：

| 候选池 | top-1 | top-3 |
|---|---:|---:|
| source-only | 45.7% | 68.1% |
| source-neighbors | 35.1% | 57.4% |
| last-3 | 0% | 0% |
| last-12 | 16.0% | 36.2% |

结论：

1. **视口是比换模型更大的杠杆**：同一 lexical 排序，知道源消息就把 top-3 从 26.5% 拉到 52.2%；
   3 条消息的“正确窗口”也有 43.5%。远处引用在无视口时是 0。
2. **即时完美视口，lexical top-3 也只有 52%**：这 48 个点就是 LLM 臂要证明的价值。
3. **池子大小直接决定 prompt 预算**：3 条消息 ≈ 30 段 / 2.6k 字符；12 条消息 ≈ 77 段 / 6.9k 字符。
   前者还能做，后者必须先预筛。

## 3. 实验臂

所有臂共用同一输入：草稿（光标前）、可见窗口、消息 id/角色、视口锚点（oracle 或估计）。
差别只在排序/生成方式。

| 臂 | 输入 | 输出 | 目的 |
|---|---|---|---|
| **A0 lexical** | 草稿 + 候选 | top-3 | 下界（已测） |
| **A1 LLM-rerank** | 草稿 + lexical top-20 | top-3 + confidence | 最小上下文、最低成本 |
| **A2 LLM-window** | 草稿 + 全部可见段落 | top-3 + confidence | 预筛是否损失召回 |
| **A3 LLM+viewport** | 草稿 + 可见段落 + 锚点/可见范围 | top-3 + confidence | 视口上下文的增益 |
| **A4 LLM-generate** | 草稿 + 可见窗口 | `continue` 文本 | 自由续写质量 |
| **A5 cascade** | A0 高分直出，否则 A1 | top-3 | 成本/质量折中 |

视口两档并行：

- **oracle**：锚点 = ground-truth 源消息（价值上限）；
- **naive**：锚点 = 最后一条 assistant 消息（线上没有滚动数据时的实际形态）。

报告每个臂在**两档**下的数字。只在 oracle 档成立的方案，必须先补视口捕获。

## 4. 指标

### 4.1 Track A：段落检索（客观）

- top-1 / top-3，按整体、近处/远处（≤3 条 vs >3 条）、草稿长度（<80 / ≥80 字符）。
- **多引用回合（105 个）**单独口径：只看最长引用的 top-1，或按多标签算 recall。
- 成对比较用 McNemar（同一批 393 回合）；报告 95% CI。
- 393 对足以检测 18 点以上的差异；不做跨用户外推。

### 4.2 Track B：拒答/误报（客观 + 人工）

- 在 2,992 个无引用回合上跑同一触发，测“触发率”和“给出建议的比例”。
- 客观代理：建议段落与最终发送文本的 Dice < 阈值，且该回合没有引用 → 记为 unhelpful。
- 人工复核 40 个“触发但无引用”的回合，判“有用 / 干扰 / 冒犯”。
- 操作点：取“召回 70% 时误报 ≤5%”的 confidence 阈值，报告该点的 precision/recall。

### 4.3 Track C：mention 检索（客观）

- ground truth：最终消息里出现、且此前窗口里出现过的 path / task id / session id。
- 指标：top-3 命中、误报；与 quote 建议共用触发。
- 这一轨与 quote 独立，可先做，因为它不依赖视口语义。

### 4.4 Track D：自由续写（人工）

- 40 条草稿，盲评 A4 与现有 reply-suggestion chip 的文本：有用 / 中性 / 有害；
- 不与 retrieval 混算。

### 4.5 Track E：成本与延迟

- 每次调用的 input/output tokens、费用、p50/p95 延迟；
- 记录“被接受的建议”成本（总成本 / 接受数），这比单次成本更接近真实价值。

### 4.6 Track F：触发（离线只能近似）

transcript 没有击键间隔，所以离线只能测“发送前一刻如果给出建议，是否正确”。
真实触发（停顿 ≥800ms）必须在接线后的 shadow 阶段测，离线不假装能测。

## 5. 上下文消融

在 A3 上逐项去掉，看每项值多少点：

| 上下文 | 预期作用 |
|---|---|
| 草稿 + 光标位置 | 基础 |
| 可见窗口（文本 + 角色 + id） | 指代对象的来源 |
| **视口锚点 / 可见范围** | 这次要定价的核心信号 |
| 最近 2–3 条用户消息 | 当前意图的延续 |
| 选区状态 | 有选区时 chip 已经赢，直接不触发 |
| 会话状态（task/goal/分支） | 后续，先不纳入 |

报告“去掉某项掉多少点”，而不是只报全量最好成绩。

## 6. 成本模型（把 ¥0.01 翻译成 token 预算）

以 3 条消息的可见窗口为例：

- 候选段落：≈2.6k 字符 ≈ 1.0–1.7k tokens（中英混合，按 1.5–2.5 字符/token 估）；
- 草稿：p50 78 字符 ≈ 50 tokens，p90 662 字符 ≈ 440 tokens；
- 指令 + 输出：≈300 tokens；
- 合计 **1.4–2.4k tokens/次**。

按 $1/M input 的量级，单次约 $0.0015–0.0025 ≈ **¥0.01–0.018**——**不预筛会压线超标**。
预筛到 12 段（≈500 tokens）后，合计 ≈0.9k tokens，单次 ≈¥0.006，才进预算。
12 条消息的全窗口（≈77 段 / 6.9k 字符）是 ¥0.02–0.03/次，必须预筛或缩窗。

调用量：430 个“引用 + 意见”回合 / 21 天 ≈ 20/天；一个回合可能停顿 2–3 次，
按 50–100 次/天估算，¥0.3–1/天。可接受。

**实测（探针 1，v4.1flash，thinking disabled）**：完整响应 p50 799ms、p95 1,151ms；
TTFB p50 557ms、p95 966ms。**p95 <800ms 对完整响应不成立**，延迟由网关/模型主导，
不随 prompt 长度线性增长。门改为 p95 <1.3s；tight-12 预筛后单次约 ¥0.008。
详见 `PROBE-1.md`。

## 7. 触发方案

**被动（要实验的主形态）**

- 用“已停多久 → 预期还会停多久”的条件剩余停时决定发起时刻：默认 t0=0.6s，
  子句边界/刚滚动时 0.4–0.6s，词中 0.9–1.2s；草稿 ≥8 字、无 IME composition、
  无命令/mention 浮层、无选区；
- lexical 预筛至少 2 个候选（否则不调模型）；
- 同一 `(draft, viewport)` 只调一次；按键只取消**显示**，不取消请求；结果按草稿前缀缓存，
  用户下一次停顿可直接显示（把“晚到的调用”变成下一次的即时建议）；
- confidence 低于阈值 → 什么都不显示（honest none）。

**显式（对照形态）**

- `@` 或 `>` 打开“引用可见段落”，候选按草稿 + 视口排序；
- 零误触发，多一个键；对键盘用户仍比鼠标选择快。

两种形态与 chip 一起做偏好盲测（§8）。

## 8. 人工评价（40 条引用 + 意见）

- 分层：近/远各 20，草稿短/长各半；多引用回合排除。
- 每条展示：草稿 + 当时的可见窗口（用 oracle 视口模拟），不给原答案。
- 盲排三臂 top-3（A0 / A1 / A3），随机顺序，标：
  1. 哪一段是我想指的（可多选 / 都不是）；
  2. 你会用这条建议替代“选中 + chip”吗（会 / 不会 / 不确定）；
  3. 若不会，原因（选段更快 / 建议不准 / 不想离开键盘 / 其他）。
- 另抽 40 条无引用回合，测“触发但没用”的干扰感。

## 9. 决策门槛（写死再看数据）

| 门 | 阈值 |
|---|---|
| 段落检索 | naive 档 top-3 ≥55%；oracle 档 top-3 ≥70% |
| 精度 | 操作点上误报 ≤5%；40 条人工复核“干扰”≤10% |
| 相对 lexical | 同池 top-3 +20 点以上 |
| 成本 | 预筛后 <¥0.01/次；p95 <1.3s（探针实测 1.15s） |
| 偏好 | 在 40 条盲测里，“替代 chip” ≥30% |
| 自由续写 | 不劣于现有 reply-suggestion chip |

任一硬门不过：

- 若 **naive 档不过、oracle 档过** → 说明价值依赖滚动位置，先补视口捕获再评；
- 若 **oracle 档也不过** → 键盘路径不做，保留 chip；
- 若 **LLM 相对 lexical 增益 <20 点** → 用 A0/A5，不上模型。

## 10. 需要捕获的最小数据（接线后再做）

发送时记录（本地，不传内容）：

```json
{
  "scrollAnchorMessageId": "…",
  "visibleMessageIds": ["…", "…"],
  "viewportHeightPx": 720,
  "selectionPresent": false,
```

这四五个字段就能把 oracle 消融换成真实读数。没有它们，所有视口结论都只是上限。

## 11. 隐私

LLM 臂会把**未发送的草稿**和可见 transcript 发给模型。与“发送后才进模型”不同。
三个选项，需先定：

1. 走现有 workers 网关（最便宜，但草稿离开本机）；
2. 本地小模型（零外发，质量待测）；
3. 只在显式触发（`@`/`>`）时外发，被动形态只用本地 lexical。

## 13. 选中即生成建议（与 quote chip 并存）

现状（见 `PROBE-2.md`）：后端 prompt 已支持 `focus`，前端只在按「建议」重抽时发送；
首次 draw 不按选中内容触发。扩展是前端触发 + 缓存键 + 合并顺序，不是新的模型能力。

### 13.1 交互

- 选中结束（mouseup/touchend，150ms 去抖、选区 4–2000 字）后：
  1. quote chip 立即显示（逐字插入，100% 精确）；
  2. 同时用 `focus` 发一次 draw；到达后把 2–3 条生成 chip 追加在 quote chip 之后；
  3. 用户点 quote chip 或开始打字 → 取消/隐藏生成 chip；
  4. 缓存键 `(sessionId, messageId, focusHash)`；同一选区不重复调用。
- 生成 chip 只在输入框为空（或只含 quote chip）时显示；有草稿时不打扰。

### 13.2 长度

- 第 1 条 ≤80 字符（较完整，回答多个待答点）；第 2、3 条 ≤40 字符（更短的决定/确认）；
  硬截断 120。
- “展开成整条消息”是显式动作（第二次调用），不放进默认批次。
- 依据：真实使用记录里第一条被点选 81%，被点选中位 39 字符、上限 114；
  生成探针在 160 上限下平均也只有 28 字符。

### 13.3 实验

- 样本：60 个引用回合（30 near / 30 far，排除多引用），每个有选中原文 + 真实 draft。
- 臂：A 现状（无 focus）/ B focus / C focus + 长度阶梯 / D focus + 160。
- 判据：`reply-suggestions-bench` 的 same/near/different（≥2 评判，保守一致度）；
  逐 chip 与逐消息命中率；长度、tokens、p50/p95 延迟。
- 人工盲评 30 条：same/near/different + “会不会用它替代自己写”。
- 决策门：B 相对 A 至少 +10 点逐消息“同或近”；C 不劣于 B 且中位 ≤60 字符；
  D 相对 C 无 ≥10 点提升则不做更长；p95 ≤1.5s；quote chip 不被生成阻塞。
