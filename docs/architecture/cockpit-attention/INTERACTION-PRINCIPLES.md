## 一句话

**一屏看全部待办，行（卡片）就是决策单元：问题、情境与默认选项的完整说明都在行里，绝大多数事项在行内一次完成；少数切换或比较选项，更少数才进入详情或会话。**

## 原则

### A. 屏幕与结构

1. **一屏优先，不切页。** 观察墙、全部项目、倡议不再是页面；没有需要切换的 tab。board 是抽屉 / 侧栏，不是路由。
2. **行是决策单元。** 每个事项自带：问题、情境、事实、**默认选项的完整说明**、一个确认、负荷与时长（详见 F 节）。目标：缺省屏上 ≥ 60% 的事项不离开这一行就能处理。
3. **救援在前。** 卡死与待确认的修复排在提问之前；系统已自动处理的折叠成一行，带「撤销」。
4. **宏观信息压进一条状态带**（Quay 管线、Gates、架构变更），需要时展开，不另占页面。

### B. 渐进披露（按频率分级；每级可选、可返回、代价可见）

| 级 | 触发 | 看到什么 | 预期占比 |
|---|---|---|---|
| L1 行 / 卡片 | 无需操作 | 问题 + 情境 + 事实 + **默认选项的完整说明** + 确认 | 约 60% 在此办完 |
| L1+ 选中 | 点行的非选项区 / `↑↓`（PC）；点卡片非选项区（手机） | 详情：完整情境、**全部选项的完整说明**、历史、会话 | 随手查看 |
| L2 换选项 / 比较 | 行内选项标签或 `←→`、`1–9`（PC）；选项下拉（手机）；详情里点选项 | 选中的选项在原位显示完整说明；详情里并排比较 | 约 20–25% |
| L3 会话 | `S` / 详情里的「Open conversation」 | 原会话（PC 在列表旁打开）；没有原会话时在目标项目开新会话 | 约 10–15% |
| L4 分支 | 在 L3 中 | 后台调查、立任务、转交、稍后 | 更少 |

5. **默认选项在行里讲完整**：做什么、因为、后果、撤销、适合什么情况。**其它选项在行里只出现名字**（PC 的标签、手机的下拉项），完整说明在详情里给出，并可在原位切换显示。
6. **选中驱动详情，悬停不驱动。** 详情永远跟随「选中的这一项」；鼠标移动不改变你正在读的内容。
7. **升级发生在原位。** 简报或摘要晚到时原位升级，不改变行高，不移动焦点。

### C. 稳定与可预期

8. **焦点不跳。** 行高固定；切换选项是原位替换文字，不弹层、不重排；新事项不插到光标之上，以「N 条新」提示；只有你主动排序才重排。
9. **一个确认，绑定当前显示的选项。** 每个动作以确认卡收尾（Enter 确认 / Backspace 取消）；自动动作必带撤销。系统提议，人决定。
10. **键盘与语音一等公民。** 见 H 节键位；Escape 永不处理（它会中断会话回合）；语音用序号指事项（「第四个，删掉」），仍走确认卡。

### D. 可视化与诚实

11. **颜色稀缺。** 颜色只表示「卡死 / 需修」与「不可逆」；其余用字形、形状、明暗区分。
12. **小可视化是固定词汇**：尝试次数 → 圆点串；同类提问的作答历史 → 三段堆叠条；流程位置 → 三步节点；子决定 → ①②③；规模 → 条；有简报的选项对比 → 迷你雷达。
13. **机械与判断必须可分辨。** ● = 机械读数（**现测**，不复述会话里可能过期的说法）；○ = 取自文本或 LLM 判断，一律视为建议。
14. **每张卡都有缺省建议，来源如实标注。** 缺省选项优先取自**助手自己的推荐**（标 ●）；助手没给推荐时，由 T1 摘要同一次调用里的**判官补一项**（标 ○，附一句理由）；提供方（如 quay-fleet）的卡由提供方给出推荐。判官的建议不冒充助手的推荐，任何缺省都只作建议、始终经确认卡，不自动执行。只有摘要不足以解释问题时（incomplete）才不设缺省，行内明说，并把默认动作换成「先展开情境」。（2026-10-28 修正：此前实现成「助手没推荐就不标默认」，导致多数卡停在「Choose an option」，偏离本节第 2、5 条与效果图。）

### E. 负荷与学习

15. **负荷可见。** 每项有负荷三格与已等待时长。
16. **每个事项记录**：到达的层级、决策耗时、采取的动作、是否用了自己的文字。这是分级估计与委托阶梯的燃料。
17. **自动的资格由证据与人批准给出**（委托阶梯 §4.3）；自动动作进入「已处理」折叠行，可见、可撤、可抽查。

## F. 行的内容与信息供给

### 18. 行要让你对「问题」和「默认选项」建立较完整的理解

| # | 内容 | 由谁生产 |
|---|---|---|
| ① 问题 | 一句话，重述，不是助手的原始收尾句 | T1 决策摘要 |
| ② 情境 | 现在是什么情况：做了什么、发现了什么、量到了什么 | T0 事实 + T1 |
| ③ 默认选项 | 名字 → 做什么 → 因为 → 后果标签 → 撤销 → 适合什么情况 | 取自助手原文；助手没推荐时由判官补位（○） |
| ④ 事实 | ● 机械读数、现测 · ○ 取自文本未核 | T0 |
| ⑤ 后果标签 | ↺ 可撤 ◷ 耗时 ⚠ 不可逆 ⏸ 阻塞 ○ 无副作用 | T1 + 检查规则 |
| ⑥ 小可视化 | 固定词汇（D.12） | T0 / 历史 |
| ⑦ 负荷 + 时长 | 决策重量与已等多久 | 估计器 |
| ⑧ 默认的来源 | ● 助手推荐 · ○ 判官推荐 | T1 抽取 |

事项类型：**ASK**（提问）、**MULTI**（一个提问含多个子决定，各自显示是否已有推荐）、**NEED**（需要你先操作）、**STK**（卡死）、**FIX**（修复待确认）。

### 19. 详情要让每个选项都「可被理解」

每个选项同样给出：做什么 · 因为 · 后果 · 撤销 · 适合什么情况 · 证据（●/○）· 你过去的先例（无先例也写「无先例」）。最后一项永远是「✎ 你自己的回复」。

### 20. 信息的三级生产（供给侧）

- **T0 机械**：免费、即时。轮数、改动文件、测试、命令、时长、类型、选项抽取、作答历史；**事实重新观测**（磁盘、任务与 driver 状态）。
- **T1 决策摘要**：每个提问一次便宜的 LLM 调用（< 10 s，无工具）：重述问题、情境、助手自己的推荐与理由、带后果标签的选项；助手没推荐时同一次调用里由判官挑出缺省项并给理由（source=judge）；上下文不足时显式标「摘要不足」。**今天的会话摘要只是上一条消息的逐字摘录，T1 是新增环节。**
- **T2 简报会话**：仅重事项，带工具，< 2 分钟：取新证据，生成该事项专属的可视化（BriefSpec），过机械格式检查，原位升级详情。见 `experiments/cockpit-briefing/`。

## G. 手机模型

驾驶舱在手机上是一个**相对会话独立的页面**；点卡片里的会话链接会跳到会话页，返回时回到驾驶舱原位（滚动位置与选中项保持）。

**会话页 header（入口，2026-10-27 确认）**——保持单行、总高 45px 不变，`☰` 与模型图标不动：
- **会话标题后**是一个「R」下拉按钮（取代原来的「● Resident ▾」标签）：进程在跑时字母和边框为绿色（淡绿底），不在跑时为灰色；没有圆点，保留一个小 ▾；点开仍是 Resident 详情。
- **项目名后**是 Quay in-flight 图（64×14，原 Resident 标签的位置），可点开完整 Quay 面板。
- 右侧依次是 tab 下拉、`⋯`、**驾驶舱按钮**。驾驶舱按钮与 `⋯` 同尺寸（32×32）、同边框样式，图标为仪表盘（gauge）；待处理数以**红底白字角标**标在右上角（> 99 显示「99+」）；为 0 时按钮变淡、无角标。
- 实测（390px）：标题可见宽度 155 → 116px（R 占用标题行，已接受）；右侧控件总宽 135 → 124px；无横向溢出。效果图 `140-header-*`、`141-header-new-compared`。

**列表**
- 顶部两行过滤：类型（All / Stuck / Rulings / Needs you / Mine）与项目（多选抽屉，带各项目待办数，可与类型叠加，按设备记住）；右侧 **Cards / Compact** 切换。
- 卡片分三个触摸区：
  - **A 区**（头部、问题、情境、事实、小可视化）：点按 = 打开 Details 抽屉；右上角 `›` 作提示。
  - **B 区**：一个**选项下拉**，标题是当前显示的选项名与来源、「k of n」；下拉里每项是富文本说明，**最后一项是「✎ Write your own」及编辑框**。选中后卡片显示该选项的完整说明（自己的回复则显示编辑框）。
  - **C 区**：**一个确认条**，标签带选项名（「Confirm · File cleanup task」）。点它先出确认抽屉，不直接发送。不可逆选项为橙色描边加 ⚠；自己的回复未输入时为灰色。
- 没有独立的 Alternatives / Details 按钮，选项标题不单独带按钮。
- **紧凑模式**：问题（≤ 2 行）+ 一行情境 + 同一行的选项下拉与 Confirm；一屏约 4 张。
- 不做「滑动即批准」；左滑仅「稍后」且可撤销；确认按钮 ≥ 48 px；软键盘弹出时确认条停在键盘上方。

**Details 抽屉**（约 90% 高）：问题与元信息 → 情境（要点、事实、助手原话）→ 「现测 vs 会话当时说的」→ 选项（同一下拉与富文本，含自己的回复）与「Compare all side by side」→ 同类提问历史 → **会话区**：
- 有原会话：「Open "<会话名>"」（轮数、最后活动、末句摘录）与「Ask in this conversation…」。
- 没有原会话：说明来源，提供「Start a conversation about this」→ 抽屉：项目（默认任务自己的项目）、可编辑的第一条消息（已预填）、要附带的上下文（勾选）、Start & send / Start empty / Cancel。
- 抽屉底部常驻同一个确认条。

**自己的回复与开新会话都和其它选项走同一条路径**：先出确认卡，再发给会话；Fleet 把它记成一条决策（可作为以后的先例）。

## H. PC 模型：右侧常驻、可收起的驾驶舱列

**布局**
- **左侧不变**：现有会话页面（会话列表侧栏 + 会话视图 + 会话输入框）。
- **右侧是驾驶舱列**（约 400px，与手机卡片同宽，可拖宽，按设备记住）。**收起时整页与今天的会话页一致**；展开/收起由 header 右侧的**驾驶舱按钮**（与手机同一图标与红色角标；展开时为按下态）及一个全局快捷键控制。
- 驾驶舱列内部：顶部是标题与收起按钮、类型 / 项目过滤、Cards / Compact；中部是**事项卡片列表（即手机卡片）**；**底部常驻驾驶舱的语音与文字输入框**。
- 断点：≥ 1280px 挤压式常驻；900–1280px 以**覆盖式抽屉**打开（点会话链接后自动收起，以免挡住会话）；< 900px 用手机模型。

**驾驶舱列只放「等我处理的」**
- 在驾驶舱输入框说「在 X 项目开个会话做 Y」：先出确认卡（项目、第一条消息、附带上下文），确认后**在左侧会话区创建并打开这个会话**，不进入卡片列表。
- 其它指令（把某个回复发给某会话、筛选卡片等）同样先出确认卡。

**卡片与左侧的联动**
- 点卡片里的会话链接：**在左侧打开该会话**，滚到产生这条事项的消息并高亮；卡片保持选中，标「已在左侧打开」。在左侧会话里直接回答，或在卡片上确认，都会让这条事项结束。
- 左侧当前打开的会话所产生的事项，在列表里置顶并标「本会话」，不另外冒出。
- 卡片的 Details 在**驾驶舱列内部推入**（带返回），不占用左侧；内容与手机 Details 抽屉相同（情境、现测对照、全部选项、自己的回复、会话区、历史），底部常驻同一个确认条。

**卡片内的操作**：与手机相同——一个选项下拉（富文本项 + 自己的回复）、一个绑定当前选项的确认条；点卡片非选项区 = 选中并可进入 Details。

**焦点归属（语音与键盘）**
- 按住说话、打字、快捷键都**归当前有焦点的那一边**；两个输入框都没有焦点时，**默认给驾驶舱**。
- 焦点在驾驶舱列时：`↑` `↓` 换卡片，`←` `→` 或 `1`–`9` 换当前卡片显示的选项（**数字键只选选项**），`E` 写自己的回复，`Enter` 确认（先出确认卡），`Backspace` 返回 / 关闭；Escape 永不处理。焦点在左侧会话时，按键全归会话。

**选中项即 hub 的服务端焦点**，所以 PC、手机遥控与语音看到的「当前事项」一致；不使用悬停预览。

**与现有界面的关系**
- 侧栏的「会话 / 驾驶舱」模式切换：PC 上由驾驶舱列的展开 / 收起取代，手机保留。
- `/cockpit` 路由保留给手机与手机遥控；PC 右侧列挂的是同一套组件，状态共享。
- 会话页顶部的 notices 通知槽改为进入驾驶舱卡片，会话页不再放横幅。
- 聊天的「输入大纲」抽屉改为贴**会话区**的右边缘（10-27 确定），不再与驾驶舱列冲突。

**早先的「列表 + 详情栏」PC 方案**（行内选项标签、全部选项详情栏、Full / Compact）保留为可选的全屏集中处理视图，不再是默认界面。

## I. 已定的决定（2026-10-26）

| 决定 | 内容 |
|---|---|
| 悬停 | 取消悬停预览；详情只跟随选中项 |
| 数字键 | `1–9` 只选选项；选事项靠 `↑↓`、点击、语音或输入框 |
| 批量确认 | 设计保留，**初期关闭**；开启前需分级与校准数据；只有可逆或无副作用、摘要完整的选项可入批；批量产生的决策在先例中降权 |
| 选项选择 | 手机用下拉（富文本项 + 自己的回复）；PC 用行内标签原位替换，不用下拉 |
| 确认 | 一个确认，绑定当前显示的选项；永远先出确认卡 |
| 没有原会话 | 在任务自己的项目里开新会话（fleet 层事项的归属规则待定） |
| 救援 | 优先推进；最好不等人，其次给出明确的处理建议待确认 |
| PC 布局（10-26/27） | 驾驶舱为右侧常驻、可收起的列；收起时与现会话页一致；入口是 header 右侧带计数的按钮，不用窄竖条 |
| 列的内容 | 只放「等我处理的」；指令创建的会话在左侧打开，不进卡片列表 |
| 焦点 | 语音与键盘按焦点归属；都无焦点时给驾驶舱 |
| 中等宽度 | 900–1280px 用覆盖式抽屉 |
| 手机 header（10-27） | 单行 45px：标题后「R ▾」（绿 / 灰）、项目名后 Quay 图（14px 高）、右侧 tab ▾ · `⋯` · 驾驶舱按钮（gauge 图标、红底角标） |
| 输入大纲（10-27） | 改为贴**会话区**的右边缘，不再贴窗口边缘 |
| 指令开会话（10-27） | 确认后在左侧创建并**立即切到**新会话 |
| 会话提问计入（10-27） | 等待满 **3 分钟**才成为卡片；该规则属于 quay-fleet |
| 系统通知（10-27） | 发哪些由 **quay-fleet** 决定，CloudCLI 只负责送达 |
| 封装与提供方（10-27） | 驾驶舱在本项目内封装；卡死、救援、等待等开发语义尽量由 quay-fleet 提供；将来可接入其它卡片提供方——见 `CARD-PROVIDERS.md` |
